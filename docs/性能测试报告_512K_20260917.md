这些结果是固定合成测试集上的改善，不能承诺每一种实际任务都同幅提速。普通文字任务的MTP最优长度可能不同；不是满512K输入的速度。模型量化质量没有在本轮作完整评估。

正常续聊缓存验证成功：保留约1.53万Token历史后追加问题，多组首字约0.6秒；这是现有KV复用的效果，不是本轮新增了缓存功能，也不是所有跨会话请求都能命中。

复测标签映射：baseline=MTP2/微批量1024/线程4；mtp3=MTP3/1024/4；balanced=MTP3/2048/4；threads8=MTP3/2048/8。首轮prefill_ub系列在各量化的MTP4筛选候选上比较微批量；最终结论以复测和长输入验证为准。

## 方法与边界

- 每组重启并预热；四类固定任务：代码、文字、数学、重复代码编辑，每项两轮、最多生成 192 Token。
- 首轮比较关闭 MTP、草稿长度 1/2/3/4、MTP=2 加 ngram-simple。另比较物理微批量 512/1024/2048。
- 复测比较原配置、MTP=3、MTP=3+微批量2048，以及再将 CPU 线程从4增加到8。
- 冷输入指模型预热后的 KV 未命中输入，不是冷磁盘加载；显式 cache_prompt=false；测试文档真实输入 15314 Token。重复与正常续聊单独启用缓存。
- 512K 是配置容量，不表示每个测试都输入了 512K；不能把本报告速度当作满 512K 的速度。
- 常规扫描关闭思考，另有开启思考的单独检查。输出 token 上限用于速度测量，不是完整能力评测。
- 同一量化、温度0也出现输出哈希变化，不能声称所有配置输出逐字一致；GPU数值路径、分块和推测解码可能影响输出。
- 表中综合生成速度按生成阶段耗时汇总，不是四项速度的简单平均；冷输入首字包括预填充。不同内容和缓存状态需分开比较。

## 参数选择与回退

候选共同配置：MTP 草稿最大长度 3，物理微批量 2048，CPU 线程 8；逻辑批量仍为4096。保持512K、单Slot、q8_0 KV、1800秒休眠与原自启动策略。最终是否应用以维护说明中的部署验证记录为准。
与此相对，原参数是 MTP=2、微批量1024、线程4。只追求短任务综合生成速度时，MTP=3、微批量1024、线程4也很有竞争力；推荐组合折中考虑长输入首字和生成。
MTP=4在代码重复任务更快，但普通文字任务有明显退步；不作为通用默认。MTP=2+ngram-simple在本机本组设置下明显退步，不采用，不外推为所有Prompt Lookup实现都无效。
缓存复用是现有能力，本轮未额外加大cache-ram，没有将冷输入与缓存命中混成一个平均值。客户端改变历史前缀、其他会话替换缓存、服务休眠/重启都可能令缓存失效。
原配置与原成功模型配置备份：/home/amd/backups/performance-512k-20260917-155508/。完整原始结果、测试脚本和最终推荐配置同时保存在该目录。
若回退参数，可在Dashboard将草稿长度改回2、物理微批量改回1024、生成CPU线程改回4，检查后保存加载；会清空当前KV并重启模型。若需要完整原配置，管理员应使用备份server.json重新生成服务策略，而不是仅覆盖文件而不更新systemd。
本轮系统报告显存预留512MiB、系统RAM约125GiB，通过大GTT使用统一内存；没有改BIOS、功耗或内核设置。测量间一次vmstat检查未见持续换入换出，但不能据此证明所有时刻无内存压力。
